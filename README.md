# 🔐 CipherLab

**pycryptodome로 현대 암호를 직접 돌려보며 배우는 학습용 웹 앱**입니다.
메시지와 파일을 여러 대칭키 암호로 암호화·복호화하면서 각 알고리즘의 동작을 눈으로 확인할 수 있습니다.

**『화이트 해커를 위한 암호와 해킹』** 책의 예제 코드(pycryptodome 기반)를 Flask 웹 앱으로 옮긴 것입니다.

> ⚠️ **학습·교육용 데모입니다.** 아래 [보안 한계](#-보안-한계-의도적으로-남겨둠)를 반드시 읽어보세요. 실제 데이터 보호에는 사용하지 마세요.

---

## ✨ 주요 기능

- **3가지 암호**(3DES · AES · ARC4)를 각각 **별도 페이지**에서 실습 (`/des3`, `/aes`, `/arc4`)
- **메시지 모드** & **파일 모드** 모두 지원 (암호화 ↔ 복호화 왕복)
- 메시지 암호문을 **Base64 / Hex** 로 즉시 전환해서 표시
- 파일은 드래그&드롭 업로드 → 결과물 다운로드 (서버에 흔적을 남기지 않음)
- 다크 테크·네온 UI (Tailwind CSS)

## 🧩 지원 암호

| 암호 | 유형 | 키 크기 | 블록 크기 | 운용 모드 | IV | 메시지 | 파일 |
|------|------|--------|----------|----------|----|:---:|:---:|
| **3DES** (Triple DES) | 블록 암호 | 24바이트 (유효 168비트) | 8바이트 (64비트) | CBC | ✅ | ✅ | ✅ |
| **AES-128** | 블록 암호 | 16바이트 (128비트) | 16바이트 (128비트) | CBC | ✅ | ✅ | ✅ |
| **ARC4** (RC4) | 스트림 암호 | 1~256바이트 (가변) | — | 없음 | ❌ | ✅ | ✅ |

### 각 암호 개략 설명

- **3DES** — DES를 세 번 겹쳐(EDE: 암호화→복호화→암호화) 적용한 레거시 블록 암호입니다.
  블록이 64비트로 작고 속도가 느려 현재는 폐기 수순이지만, 블록 암호와 CBC 모드를 이해하기에 좋은 예제입니다.
- **AES-128** — 오늘날의 표준 대칭키 블록 암호입니다. 128비트 블록에 10라운드 치환·확산을 적용합니다.
  이 앱에서는 CBC 운용 모드를 사용합니다.
- **ARC4 (RC4)** — 키에서 **키스트림**을 만들어 평문과 XOR하는 스트림 암호입니다.
  블록·패딩·IV가 없어 구조가 단순하지만, 알려진 취약점으로 실무에서는 폐기되었습니다(학습용으로만).

> **키/IV 유도 방식**
> 블록 암호(3DES·AES)는 패스프레이즈의 `SHA256` 해시에서 키와 IV를 잘라 씁니다.
> ARC4는 패스프레이즈 바이트(`keytext.encode()`)를 **그대로** 키로 사용합니다(해시·IV 없음).

## 🚀 빠른 시작

### 요구 사항
- Python **3.12+**
- [uv](https://docs.astral.sh/uv/) (의존성·가상환경 관리)

### 설치 & 실행

```bash
git clone https://github.com/MindGeometer/cipherlab-pycryptodome.git
cd cipherlab-pycryptodome

uv sync                    # 의존성 설치 (.venv 자동 생성)
uv run python app.py       # http://127.0.0.1:5000 에서 실행
# 또는: uv run flask --app app run --debug
```

브라우저에서 **http://127.0.0.1:5000** 접속 → 암호 카드를 선택해 시작합니다.

### 테스트

```bash
uv run pytest              # 91개: 메시지·파일 라운드트립 (엣지 케이스 포함)
```

## 📖 사용법

| 모드 | 사용 방법 |
|------|-----------|
| **메시지** | 키(·IV) 입력 → 평문 입력 → **암호화** → 암호문(Base64/Hex) 확인. 반대로 암호문 붙여넣고 **복호화**. |
| **파일** | 키(·IV) 입력 → 파일 드래그&드롭 → **암호화**(`이름.enc` 다운로드) 또는 **복호화**(원본 다운로드). |

- **Base64 / Hex 토글**: 메시지 암호문의 표시 형식을 바꿉니다. 같은 바이트를 다르게 적을 뿐이며, 복호화 시에도 선택한 형식으로 해석합니다.
- ARC4는 스트림 암호라 **IV 입력란이 없습니다**.

## 🔧 원본 예제 대비 수정 사항

원본 책 코드의 인터페이스(passphrase→SHA256 키/IV, header+filler 패딩, ARC4 raw 키)는 **그대로 유지**하되,
아래 결함들을 수정해 모든 입력에서 정상 동작하도록 했습니다.

| 항목 | 문제 | 수정 |
|------|------|------|
| **파일 BUG 1** | 단일 청크 + `헤더+파일크기 ≥ 1024`인 파일(예: 3DES 1017~1023B)에서 filler 누락 → `encrypt()` padding 오류 | filler를 읽기 루프 이후 파일 크기 기준으로 **무조건** 추가 |
| **파일 BUG 2** | 암호문 본문이 정확히 1024 배수일 때 마지막 청크를 못 잡아 filler가 복호 결과에 잔존 | 전체 크기로 `remaining`을 계산해 마지막 청크 판별 |
| **멀티바이트 패딩** | 패딩을 '문자 수'로 계산해 한글 등 UTF-8 멀티바이트에서 정렬이 깨짐 | UTF-8 '바이트 수' 기준으로 계산 |
| **3DES 메시지 패딩** | 원본 3DES 메시지 코드는 패딩이 없어 8배수 아닌 입력에서 crash | AES와 동일한 header+filler(블록 8) 적용 |
| **ARC4 파일 모드** | 원본에 없던 기능 | 스트림 특성상 헤더/filler/IV 없이 청크 스트리밍으로 추가 |

## 🛡️ 보안 한계 (의도적으로 남겨둠)

교육용 원본의 특성을 보존하기 위해 다음은 **수정하지 않았습니다**. 그래서 실무 암호로는 부적합합니다.

- 패스프레이즈를 salt·반복 없는 **단일 SHA256**으로 키 유도 (제대로 된 KDF 아님)
- IV가 패스프레이즈에서 **결정적으로** 생성됨 (매 암호화마다 랜덤이 아님)
- `'0'` / `#` 문자 기반 **비표준 패딩**
- **무결성 검증(MAC/AEAD) 없음**
- **ARC4는 폐기된 취약 암호**이며, 3DES도 사용 중단 권고 대상

> 실무에는 **AES-256-GCM + PBKDF2/scrypt + 랜덤 IV/nonce**를 사용하세요.
